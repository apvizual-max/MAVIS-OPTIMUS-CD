## 2. The Single-Branch Main-Only Invariant

To ensure that multiple agents working asynchronously never suffer from drift, orphaned code, or git merge hell:
- **`main` (or `master` where configured) is the single source of truth.**
- Every branch created by Jules (`jules-*`, `sentinel/*`, `palette/*`, `bolt/*`) is strictly ephemeral.
- As soon as Jules finishes its work and creates a Pull Request:
  1. Antigravity inspects the diff (**Engineering Second-Eye Review**).
  2. Runs syntax, linting, and structural validation.
  3. Verifies that no security regressions or secrets were introduced.
  4. Merges the PR into `main` using **Squash and Merge** (consolidating commits into a clear, semantic title and description).
  5. **Immediately deletes the remote branch.**
  6. Updates the repository's `JULES_HANDOFF.md` ledger.

## 5. Web Inbox & Notification Zero (Done vs Read)

A critical distinction discovered during system operation:
- **`PUT /notifications` (Mark as Read):** Resets notification counters in CLI tools, but on the GitHub Web UI (`github.com/notifications`), threads remain in the Inbox view.
- **`DELETE /notifications/threads/:thread_id` (Mark as Done):** Acknowledges and completely removes threads from the GitHub Web Inbox.
- **Requirement:** Antigravity must execute `DELETE /notifications/threads/:id` on all active threads to achieve 100% web dashboard cleanliness.
